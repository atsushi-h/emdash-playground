# Cloudflareデプロイ仕様

作成日：2026-11-03

状態：ヒアリングで決定した仕様を記録。実装・リモートリソース作成・デプロイは未実施。

## 目的

既存のEmDashサイトをCloudflareへデプロイし、自分のGoogleアカウントだけで閲覧・管理できる検証環境として運用する。独自ドメインは取得せず、Cloudflareの提供するURLを使う。

## 決定事項

| 項目               | 仕様                                                                                                                               |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| ホスティング       | Cloudflare Workers。Astroのサーバーレンダリングを維持する                                                                          |
| URL                | `workers.dev`。独自ドメインは不要                                                                                                  |
| CMSデータ          | Cloudflare D1                                                                                                                      |
| 画像・メディア     | Cloudflare R2。公開バケットや公開URLでアクセス制限を迂回させない                                                                   |
| アクセス制限       | Cloudflare Accessで記事・画像・管理画面・APIを含むサイト全体を保護する                                                             |
| 認証               | Googleアカウントでログインし、指定する自分のメールアドレスだけを許可する                                                           |
| 管理画面           | EmDashのCloudflare Access連携を使い、Googleログイン後に追加のEmDashログインなしで入れる構成を目指す。自分に管理者権限を割り当てる  |
| 初回データ         | ローカルの記事・固定ページ・画像など、現在のCMSデータをバックアップして移行する                                                    |
| 移行後の更新       | Cloudflare上のデータを正とし、本番管理画面から更新する。ローカルとの自動同期は設けない                                             |
| デプロイ手段       | 最初からGitHub Actionsを使う                                                                                                       |
| 通常の本番デプロイ | `main`へのpush・マージで自動実行する                                                                                               |
| PR                 | チェックとビルドのみ実行する。PR用プレビュー環境は作らない                                                                         |
| 初回起動           | GitHub Actionsを手動起動し、アクセス制限・データ移行を検証してから通常の自動デプロイを有効にする                                   |
| 費用               | 無料枠内の運用を目指す。R2の利用開始手続きと無料枠超過時の従量課金は許容する。追加の有料プランが必要になった場合は導入前に判断する |

## 初回デプロイと移行

1. 導入中のEmDashバージョンと、Cloudflare Access連携への対応を確認する。必要な更新がある場合は変更内容を明確にする。
2. 対象のCloudflareアカウント、許可するGoogleメールアドレス、Workers・D1・R2のリソース名を確定する。
3. Cloudflare AccessとGoogle認証を設定する。最初の起動からサイト全体を保護し、設定完了まで未認証でコンテンツを取得できる状態を作らない。
4. ローカルのCMSデータとメディアを整合性のある形でバックアップし、復元方法を確保する。
5. GitHub Actionsを手動起動してデプロイし、保護された環境へデータとメディアを移行する。メディアの参照も移行先で成立させる。
6. 下記の受け入れ条件を検証し、問題があれば保護を維持したまま修正する。
7. 検証完了後、`main`更新による通常の自動デプロイを有効にする。

既存データベースの初期化や再seedで移行を代替しない。初回移行後のデプロイはコードの更新とし、CMSのコンテンツやメディアをローカルの状態で上書きしない。

## GitHub Actions

- PRではリポジトリ標準のチェックと本番向けビルドを行う。
- 初回用に手動起動できる経路を用意する。
- 初回検証前は`main`更新による本番への自動デプロイを無効にする。
- 初回検証後は、チェックとビルドの成功を条件に`main`更新を本番へデプロイする。
- デプロイ資格情報はGitHubのSecrets等で管理し、ソースコードや実行ログに出力しない。PRのチェックには本番のデプロイ資格情報を渡さない。
- ワークフローの再実行でデータ移行や初期化が繰り返されない構成にする。

## 受け入れ条件

- `workers.dev`のURLでサイトを利用できる。
- 未認証では記事本文・画像・管理画面・APIの保護対象データを取得できない。
- 許可していないGoogleアカウントは拒否される。
- 許可した自分のGoogleアカウントでサイトを閲覧でき、EmDash管理画面では管理者として操作できる。
- R2の公開URLや別のデプロイURLなど、認証を迂回してコンテンツを取得できる経路がない。
- 現在のローカルCMSデータと画像が移行され、ページや画像参照が正常に表示される。
- 管理画面から記事の更新と画像のアップロードができる。下書きが通常の閲覧で露出しない。
- 既存の検索と予約公開・メンテナンス処理がデプロイ先で動作する。
- PRではチェックとビルドだけが実行され、本番へのデプロイは行われない。
- 初回検証完了後、`main`更新でGitHub Actionsから本番へデプロイされる。
- 本番で記事・画像を更新した後に再デプロイしても、その変更が保持される。

## 実装時に確認する事項

以下は未確定の接続情報・技術的確認事項であり、上記の合意を変更するものではない。

- 利用するCloudflareアカウントと権限、Googleの許可メールアドレス。
- Google OAuthクライアントおよびCloudflare Accessの既存設定の有無。
- 導入中のEmDashとAccess連携の互換性、管理者権限の割り当て方法。
- ローカルデータとメディアの実体、バックアップ・移行・復元の具体的な手順。
- GitHub Actionsの資格情報、リソース識別子、初回検証後の自動デプロイ切り替え方法。
- Accessの保護を初回起動から成立させる具体的な設定手順。
- Workers・D1・R2・Accessの最新の無料枠と、既存のCron処理を含む本構成の適合性。

## 対象外

- 独自ドメイン。
- 自分以外の利用者へのアクセス付与。
- PRごとのプレビュー環境。
- ローカルとCloudflare間のCMSデータの自動同期。
