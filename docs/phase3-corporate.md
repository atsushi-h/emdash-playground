# ミナトテック 固定ページ・企業サイト外観（フェーズ3）

EmDash 1.4.0 / Astro 7.4.4の既存PoCに、トップ・固定ページと共通デザインを追加しました。架空企業の検証用サイトです。送信フォーム、メール配信、Turnstile、問い合わせ個人情報の保存は未実装です。本番デプロイは行っていません。

## ローカルで確認

```sh
bun dev --host 127.0.0.1 --port 4322
```

- トップ：<http://127.0.0.1:4322/>
- 固定ページ：`/company/`・`/services/`・`/privacy/`・`/contact/`
- 既存機能：`/news/`・`/works/`、旧`/posts`からの転送
- 管理画面：<http://127.0.0.1:4322/_emdash/admin/content/pages>
- ローカル開発用ログイン：<http://127.0.0.1:4322/_emdash/api/auth/dev-bypass?redirect=/_emdash/admin/content/pages>

開発用ログインは標準機能で本番では無効です。同じチェックアウトの開発サーバーを重複起動しないでください。

## 見た目の変更

通常のCSSとAstroコンポーネントを使用しています。UIライブラリ、外部フォント、画像素材の依存追加はありません。

`src/styles/theme.css`の`:root`が共通設定です。`--color-*`で色、`--font-*`で書体、`--text-*`で文字サイズ、`--space-*`で余白、`--content-width`・`--reading-width`で最大幅、`--radius-card`で角丸を変えられます。ページ・コンポーネント固有の配置は各Astroファイルの`<style>`に置き、同じ変数を参照します。

ヘッダー、フッター、パンくず、ページタイトル、問い合わせCTA、お知らせ一覧、実績カードを共通化しています。スマートフォンではナビを折り返して全項目を表示します。スキップリンク、キーボードのフォーカス、長文の折り返しを用意しています。

トップの図はCSSだけで作成した抽象的な装飾です。実在する工場・設備の写真や製造図面ではありません。実績画像は既存CMSのメディアを参照し、「架空製作例・模式図」と表示します。`fixtures/works/`とフェーズ2の補助機能は保持しています。

## CMSで編集する内容

既存`pages` Collection（表示名「固定ページ」）を利用します。`drafts`・`revisions`・`preview`・`search`・`seo`を維持しています。

| 内部名         | 型                 | 用途                                                                |
| -------------- | ------------------ | ------------------------------------------------------------------- |
| title          | string・既存必須   | ページタイトル                                                      |
| content        | portableText・既存 | 挨拶、アクセス、事業の詳説、ポリシー、問い合わせ案内                |
| lead           | text               | 導入文。company/servicesはトップにも表示                            |
| featured_image | image              | 任意のページ画像                                                    |
| postal_code    | string             | companyの郵便番号                                                   |
| address        | text               | companyの所在地。フッター共通                                       |
| phone          | string             | companyの電話。PoCでは空、発信リンクなし                            |
| business_hours | string             | companyの営業時間。フッター共通                                     |
| company_facts  | repeater           | 基本情報。label:string・value:text、最大20行                        |
| service_items  | repeater           | title:string・summary:text・image:image・description:text、最大12行 |

追加フィールドはすべて任意です。repeaterの行を作る場合、会社基本情報の項目名・内容、事業の名称・概要は必須です。repeater内にPortable Textは置けないため、リッチテキストはページ本文で編集します。

用途別フィールドも同じ編集画面に表示されます。「会社概要用」はcompanyだけ、「事業内容用」はservicesだけに入力してください。Singleton・フィールドの条件付き表示・独自ページビルダーは実装していません。

会社名は標準Settingsのサイト名に一本化しています。会社概要の「会社名」とヘッダー・フッターは同じ設定を表示します。会社基本情報に会社名・所在地・電話等を重複入力しないでください。会社名・ロゴ・favicon・タイムゾーン・日付形式・共通SEOは標準Settings、ナビは標準のprimary/footerメニューで管理します。既存記事の日付は引き続き日本語・Asia/Tokyoです。

トップ専用フィールドはありません。Settings、company/servicesの内容、公開works3件、公開posts3件から組み立てます。事業のトップ抜粋は先頭2件です。

## 管理画面での確認手順

1. 「固定ページ」→「会社概要」を開く。所在地・営業時間などを変更し「保存」する。
2. 「下書きをプレビュー」で、会社概要とフッターの両方に同じ変更が出ることを確認する。未ログインの通常URLでは公開版のままであることを確認する。
3. 「変更を公開」で一般表示へ反映されることを確認する。再起動・再ビルドは不要。
4. 「事業内容」を開き、「事業内容用：事業一覧」の概要・説明を変更する。行は追加・削除・並び替えでき、画像は未設定でもよい。
5. 保存→プレビュー→公開し、事業ページとトップの抜粋が更新されることを確認する。
6. 会社概要本文の代表挨拶・アクセスを標準リッチテキストで編集する。
7. privacy/contactも標準本文とSEOパネルで編集できる。contactには本文とは別に固定の受付未提供案内が出る。

ユーザー自身による最終操作確認はこれからです。エージェントによる管理画面の所在地変更・更新下書き保存・破棄は確認済みです。

## 固定slug・公開解除・プレビュー

- `company`・`services`・`privacy`・`contact`は固定slugです。変更しないでください。Astroの個別ルートがそのslugを取得します。
- slugを変更すると元の固定URLは取得できなくなります。変更先は汎用ページとして本文を表示しても、会社概要の基本情報や事業カード・トップ抜粋・フッター連携は引き継ぎません。誤変更したら同じ記事のslugを戻してください。自動で別記事を採用しません。
- 既存Aboutと本文・履歴は保持し、`/about/`で閲覧できます。ナビの会社概要は`/company/`へ変更しました。
- company/services/privacyの未存在・一般閲覧の下書きは404です。company非公開時はフッターの所在地等とトップの紹介も省略します。Settingsのサイト名は残ります。
- contact本文が未公開でも、固定の受付未提供案内と他ページへのリンクを200で表示します。未公開本文は表示しません。取得障害はフォールバックせず503です。
- 標準署名プレビューとSEOを使用します。プレビューは確認表示、noindex/nofollow、private/no-store。ヘッダーは配信開始前のルートで設定します。他記事用トークンではその記事の下書きを表示しません。
- 固定ページと汎用ページのスラッシュなしURLは308転送し、クエリを保持します。標準プレビュー発行URLがスラッシュなしでも署名を維持します。
- `src/middleware.ts`は共通Settings・メニュー・会社情報をHTML配信前に取得し、失敗時503/no-storeを返します。EmDashの内部ルートは除外します。全依存のcacheHintを登録します。ルートキャッシュは新たに有効化していません。

## 既存DBと新規環境用seed

**seedの変更は既存DBへ自動適用されません。既存DBへのseed再投入・初期化はしないでください。**

1. 対象URL・起動プロセス・DB/R2を確認し、開発サーバー停止中に整合したバックアップを取る。
2. 既存pagesのフィールド・supports・URLパターンと、固定slugの競合を調べる。
3. 任意フィールド・ラベル・URLパターン`/{slug}/`、不足メニューを標準管理機能で追加する。既存記事の内容は変更しない。
4. 同名ページがなければ4ページを下書き作成し、プレビューで内容確認後に公開する。同名ページを自動上書きしない。
5. pagesの標準検索をtrigramで有効化する。日本語の部分一致は3文字以上で検索する。
6. 型生成とコードの確認を行う。`emdash-env.d.ts`は手編集しない。

ローカル専用の標準API補助スクリプトがあります。接続先は明示的な`http://127.0.0.1:PORT`のみです。

```sh
bun scripts/phase3-corporate.ts schema http://127.0.0.1:4322
bun scripts/phase3-corporate.ts drafts http://127.0.0.1:4322
# 下書きの内容を確認してから実行する
bun scripts/phase3-corporate.ts publish http://127.0.0.1:4322
bunx --no-install emdash types --url http://127.0.0.1:4322
```

`schema`は既存フィールドの型・必須・validation、Collectionのsupports・URLを検査します。途中で失敗した場合は適用済みの段階を確認して再開してください。既存の用途外メニュー項目は残します。会社概要が`/about/`に向く項目は`/company/`に切り替え、計画の項目を並べた後に他の項目を保持します。再実行はメニュー順とラベルをこの計画へ揃え直すため、運用後のカスタマイズ時には必要箇所のみ管理画面で適用してください。

`drafts`は同名ページを上書きしません。`publish`は未公開ページのデータがseedと完全一致する場合だけ公開します。既に公開済みなら変更しません。編集済み下書きは管理画面で確認して公開してください。

新規環境はseedでモデル・設定・メニュー・架空の固定ページを初期構築します。その後必要に応じて`schema`で日本語検索を設定します。既存の実績デモ登録はフェーズ2手順のままです。

## プライバシーと問い合わせの範囲

問い合わせフォーム・送信処理・メール配信・Turnstile・個人情報保存は追加していません。架空の所在地、電話、メール、外部地図、解析タグは初期登録していません。

ポリシーは、現状の閲覧機能と管理画面認証、実運用環境で確認が必要なアクセスログ・Cookie、後続で決める取得項目・保存先・期間・窓口を分けて記載しています。「個人情報を一切処理しない」等の未確認事項は断定していません。実サービスへ転用する前に、実際の取扱いと整合させて内容を確定してください。

## バックアップと復元

適用前と比較し、既存posts22行・works22行・About1行の全既存列が一致しています。R2メディア5ファイルもファイル一覧とバイト列が一致しています。新規固定ページ4件だけを追加しています。

適用前バックアップは`.wrangler/backups/20261031-103827-phase3/state/`、比較記録は同ディレクトリの`content-before.json`です。サーバー停止中にD1/R2等をコピーし、コピー側のコンテンツDB整合性検査は成功しています。バックアップ、セッション、検証記録はGit対象外です。

検証した4ページは公開版へ戻し、検証用住所や長文・SEOの下書きは残していません。検証履歴はCMSのリビジョンに残ります。

通常の取り消しはナビ・コードを戻す方法を優先し、新規ページやメディアの削除は不要です。全データの復元が必要な場合はサーバーを停止し、その時点のstateも別途保管してからバックアップのstateを戻してください。稼働中にDBを差し替えないでください。
